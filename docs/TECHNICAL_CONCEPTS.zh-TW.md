# ITHERLA 公開技術概念

更新日期：2026-11-25 · [English](TECHNICAL_CONCEPTS.en.md) · [產品與進度](PRODUCT_PROGRESS.zh-TW.md)

本頁說明設計方向，不公開原始碼、內部契約、演算法或受限資料。各項成熟度以進度頁為準。

ITHERLA 想做的是一個能在你允許的範圍內一起玩的 Agent。換模型，不必換搭檔；
記得怎麼一起玩，也不代表 Agent 有權繼續操作。

## 概念架構

```text
Game Screen / Audio / Action Feedback
                  |
                  v
          Perception System
      Separate Sources and Align Cues
                  |
                  v
        Context Resolver (CXR)
          Interpret the Situation
                  |
                  +<--- Governed Memory
                  |
                  v
          Model: Propose an Action
                  |
                  v
          Permission Check <--- Player: Authorize / Revoke
                  |
                  +-- Eligible ------> Game Action Path
                  +-- Not Eligible --> Do Not Execute

Player: Stop / Take Over ------------> Game Action Path
```

這是責任分工圖，不是實際接線圖。感知系統整理當下的訊號，CXR 判讀情境；記憶是
參考，不是新的觀察或授權。玩家停止或接管，不需模型同意。

## 權限設計：模型能提議，不能替自己授權

模型之外的系統依玩家的有效授權、當前任務與允許範圍，判定操作是否具備資格。
模型信心、過去的操作經驗或更換推理引擎，都不會自行擴大權限。停止或撤回後，
先前排隊或晚到的模型提議不能成為繼續操作的理由。

**已驗證：** 核心資格判定已接上隔離資料庫。必要紀錄缺失，或在讀取過程中變更時，
該次資格判定不會通過。**待驗證：** 真實遊戲輸入、玩家接管與撤回後停止操作的端到端流程。

## 同樣是「送出」，情境不同

- **遊戲場景：** 你請 Agent 把集合點傳給隊友。若你已授權它在這一局使用隊伍訊息，
  Agent 可在範圍內協助，不必每次送出都問你。
- **現實場景：** 遊戲還開著，但你切到工作聊天室。即使畫面上也有「送出」，原本的
  遊戲授權仍不適用。Agent 可以幫你擬稿，但不能沿用這份授權替你發出工作訊息。

CXR 協助區分當下情境；獨立的權限判定才決定操作是否具備資格。上述是設計示例，
不是已上線功能。

## 感知與場景理解

畫面、聲音、操作回饋和其他輸入，先區分來源與情境，再一起理解。背景影片可能和遊戲
同時播放，但不代表兩者的聲音和畫面屬於同一事件。Agent 發出控制輸入，也不代表遊戲
確實做出了預期動作。

我們會比較純演算法與加入可替換的輕量多模態模型兩種做法，例如測試 EmbeddingGemma 2
是否有助於整理當下的感知訊號。只有關聯判讀或效率有實質改善、且遊戲負載可接受時，
才考慮採用。這是感知候選，不是第二套記憶召回，也沒有預先選定產品模型。

## 本地優先與雲端支援

Agent 身分與受治理的記憶不屬於任一模型。日常推理以本地為預設，依任務與設備負載決定
是否使用已授權的混合運算；必要時才使用經同意的純雲端推理。雲端用量和資料外傳是分開的
決定：已核准的一般調用不用反覆確認，敏感資料優先在本機去敏，必要外送才另行確認。

停止或撤回後，遲到的結果不應繼續影響任務；本機停止不代表已送達的資料能被遠端收回。
雲端可用於提問、查詢或能力補位，不用來產出蒸餾其他模型的訓練資料。

## 記憶、技能與權限

原始紀錄、感知、事實、情緒、Agent 記憶、技能和媒體有各自的用途與生命週期。使用者
能回看原文，不等於 Agent 可以自動召回；記得怎麼做，也不等於有權做。共享與遷移要保留
來源與用途限制，受保護的資料不因匯出而變成可攜。容量治理也應避免某一位 Agent
擠壓其他 Agent 的受保護空間。

## 年齡情境與聊天室連續性

需要證明年齡門檻時，規劃採用可信第三方的最小揭露證明，而非模型估齡或自行收存證件。
資格更新可在原聊天室生效，不必換 Agent 或重開對話。一般互動和受限功能分開，
資格變更不會自動開啟跨會話記憶或帶回先前未獲准讀取的對話。尚未選定驗證方或完成驗收。
