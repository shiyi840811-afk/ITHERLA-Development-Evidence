## ITHERLA 是什麼

ITHERLA 是一套以玩家為中心、local-first、模型可替換的遊戲 AI Agent 系統。

它的目標不是做一個只會回答問題的遊戲聊天框，而是讓同一位 Agent 能在使用者明確
授權下，跨本地、雲端與混合模型延續身分、記憶、技能與協作脈絡，並在支援的遊戲中
安全地觀察、溝通與參與。

模型是可替換的推理引擎，不是記憶、身分或工具權限的所有者。使用者始終保有開始、
暫停、修正、撤回與停止的主權。

## 我們想解決的問題

### 1. 更換模型，不應讓 Agent 從零開始

不同平台與本地模型各有所長，但切換模型常會失去脈絡、習慣與長期協作經驗。
ITHERLA 將 Agent 身分與受治理記憶置於模型之外，使推理引擎可以替換，而 Agent 的
連續性不必因此歸零。

### 2. 記得很多不等於擁有更多權限

記憶、情緒、熟悉度、模型信心與長期互動都不能自行產生工具或行動權限。系統把
觀察、理解、記憶、授權與執行分開處理，避免「知道使用者很多事情」被誤解為
「可以替使用者決定」。

### 3. Agent 需要能合作，也需要被公平治理

使用者未來可以與多位 Agent 協作。每位 Agent 的私人記憶、熟練度與經驗保持隔離；
共享技能只共享適合共享的程序。記憶容量競爭不能由比較強勢、比較會表達或模型能力
較高的 Agent 決定，最終資源治理仍由使用者掌握。

### 4. 長期記憶需要生命週期，而不是無限堆積

系統規劃將短期脈絡、持久記憶、技能、證據與大型媒體分層管理。重複內容可以整理，
經驗可以抽象成可重用概念，但來源、反例、修正歷史與回退能力不能因此消失。

### 5. 學習外部內容不能變成商業抄襲

Agent 可以閱讀、討論、比較與抽取一般概念，但合法存取不等於取得改作、再散布或
商業使用權。ITHERLA 規劃保留來源與權利狀態，區分討論、引用、概念抽取、私人實驗、
衍生創作與商業發布；權利不明時不會自動進入商業可用流程。

### 6. 安全不能只靠模型自覺

模型輸出預設只是候選。實際能力仍須經過身分、當下意圖、使用者授權、能力範圍、
受管執行環境與執行前驗證。元件故障時優先局部降級；無法證明安全邊界時停止相關
能力，而不是悄悄繞過治理。

## 公開設計原則

- **Local-first**：私人記憶與核心資料優先留在使用者控制的裝置。
- **模型可替換**：支援本地、雲端與混合運算，不把 Agent 綁死在單一模型供應商。
- **人類主導**：高影響、不可逆或跨權限行為需要清楚且可撤回的使用者授權。
- **記憶不升權**：連續性、親密度、能力與信心不會自行產生控制權。
- **錯頻可修正**：錯誤理解保留修正與回錨路徑，不以懲罰或刪除歷史維持表面一致。
- **可攜但不越界**：使用者能帶走合法可攜的記憶與技能；公司機密、第三方限制與
  私人資料仍保有各自邊界。
- **可停止、可恢復、可審查**：系統要能安全暫停、回退、診斷並說明目前限制。
- **不以安全宣傳取代驗證**：任何能力都必須經過實際測試才會宣稱支援。

## 我們如何看待 AI 安全

感知資料、工具結果、記憶與模型輸出預設不帶權威。證據可以支持或修正判斷，但只在
其適用範圍內成立，並可被新證據修正；它不是終局真相，也不會自行產生授權。

ITHERLA 不允許單一模型同時掌握推理、Agent 身分、記憶、授權、執行，以及對自身
行為的最終審查權。

因此，可解釋性、事件紀錄、權限驗證與審查能力不依賴單一推理模型。模型可以被
替換、失效或降級，而治理與審查邊界仍應保持有效。

這項設計不建立在對特定模型或供應商動機的假設上，而是為了避免任何單一元件形成
無法被其他元件獨立驗證的權力閉環。ITHERLA 也不假設任何模型永遠正確，或把安全
寄託在模型願意自我克制。

系統將觀察、理解、記憶、技能、授權與執行分層處理。模型輸出首先只是候選內容；
記憶、熟悉度、信心、歷史成功與技能本身，都不能自行產生工具或行動權限。涉及外部
效果時，仍須重新核對 Agent 身分、使用者當下意圖、有效授權、能力範圍與執行邊界。

安全設計採取下列原則：

- **權限不由模型持有**：模型可以推理及提出方案，但不能自行建立或擴張授權。
- **記憶與能力分離**：記得如何完成一件事，不代表現在有權執行。
- **高影響行為重新驗證**：不可逆、敏感或跨越邊界的行為，必須取得相符的使用者授權。
- **局部故障、局部降級**：單一元件失效時，優先停止受影響能力，不讓故障穿透整套系統。
- **可以停止與回退**：系統需要保留診斷、暫停、撤回、版本回退與人工接管路徑。
- **不宣稱零風險**：安全不是一次認證後永久成立，而是持續驗證、紅隊測試與公開修正
  的工程過程。

ITHERLA 的目標不是建立一個「永遠不會犯錯」的 Agent，而是讓錯誤不容易直接取得
權限，發生偏移時能被看見、限制、修正並安全停下。

## 我們如何看待 AI 時代的失業焦慮

AI 能力快速成長，也讓許多人擔心自己的經驗、工作與學習速度會被時代拋下。ITHERLA
不承諾消除失業，也不把 AI 描述成所有社會問題的答案。

我們選擇的方向，是讓 AI 成為使用者能理解、治理、替換並長期協作的工具，而不是
要求人類把判斷權交出去。

在 ITHERLA 的設計中：

- 人類負責目的、價值取捨、授權與最後責任。
- Agent 協助整理資訊、延續經驗、學習程序並降低重複工作。
- 模型可以替換，使用者累積的合法記憶與技能不必跟著單一平台消失。
- 系統鼓勵雙向修正，不把使用者訓練成只會接受 AI 結論的人。
- 遊戲作為第一個產品場景，讓接觸 AI 可以先從興趣、合作與低壓力體驗開始，而不是
  要求每個人先成為提示工程師。

我們相信，面對 AI 帶來的改變，較健康的方向不是讓人與 AI 互相取代，而是讓更多人
能帶著自己的判斷、經驗與 Agent 組成可持續協作的小隊。

這不保證任何人的工作永遠不受影響，但它試圖保留一件重要的事：人在使用 AI 之後，
仍然能思考、能選擇、能拒絕，也能把累積的能力帶往下一個階段。

## 最近新增的公開方向

**感知：先分清來源，再一起理解場景。** 例如遊戲畫面和配樂可以共同形成場景氛圍，
但背景影片的聲音不等於遊戲事件，隊友語音也不等於玩家指令。場景感受可以成為
記憶候選，但不是事實或操作權限。這是設計方向，真實感知與產品接線尚未完成。

**推理：本地維持連續性，雲端按需支援。** 本地宿主保有 Agent 身分、受治理記憶與
任務進度；模型按需求選用，雲端用量許可與資料外傳許可分開。在本地先減少不必要
的資料揭露，超出既有允許範圍時先確認，不把切換模型等同移轉 Agent。

1. 建立整體與個別 Agent 的記憶容量治理，避免 Agent 之間因能力、語氣或關係強弱
   產生不公平的資源排擠。
2. 建立 Rights & Provenance Gate，使來源追蹤、用途分類與商業輸出資格彼此分離。
3. 讓使用者可授權 Agent 協助管理，但 Agent 不能自行擴張授權、轉授或犧牲其他
   Agent 的受保護空間。
4. 將視覺、聽覺、觸覺、聊天與外部資料視為可分離的感知來源；先保存來源、時間與
   情境邊界，再由後續認知層判讀，避免遊戲、影片、使用者與 Agent 的事件互相錯認。
5. 將感知、安全評估、情緒、事實、Agent 記憶、Skill、來源封存與大型媒體分開治理；
   寫入完成不代表形成事實、記憶、權限或可被主動召回。
